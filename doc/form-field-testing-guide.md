# CRM 表单字段测试与调试指南

本文总结通过 `opencli xbb` 创建 CRM 数据时，构造 `dataList`、定位接口错误和沉淀真实测试用例的经验。

## 1. 先获取字段解释

创建或编辑前，先查询对应表单：

```powershell
opencli xbb form-get --formId <FORM_ID> -f json
```

- `attr` 是 `dataList` 的字段名。
- `attrName` 是业务显示名称，用于理解字段含义。
- `required` 为 `1` 的字段需要填写；但选项联动可能让部分字段只在特定选项下必填。
- `fieldType` 用于判断数据形态，不能只根据中文字段名猜测。
- `items` 非空表示字段有预设选项。

## 2. 选项字段

`items` 非空时，使用 `items[0].text` 作为稳定的初始测试值：

```json
{
  "text_17": "了解需求",
  "text_18": "竟品赢单"
}
```

- 单选字段传字符串：`"text_2": "有效沟通"`。
- 多选字段传字符串数组：`"array_1": ["负责人"]`。
- 不要根据字段名称推测“是”或“否”；不同租户的选项文本会不同。
- `items[].fieldMap` 表示选择该选项后会启用的联动字段。选择该项时，应同时填写其 `fieldMap` 中列出的字段。

## 3. 常见数据形态

| 字段类型 | 常用测试值 | 注意事项 |
| --- | --- | --- |
| 单行/多行文本 | `"OpenCLI 测试-${timestamp}"` | 使用时间戳避免重复。 |
| 数字 | `0`、`1`、`100` | 传 JSON number，不要传数字字符串。 |
| 日期 | Unix 秒时间戳 | 计划、拜访等未来事件必须大于当前时间。 |
| 单人员字段 | `"<userId>"` | 以表单解释和接口错误为准。 |
| 负责人/多人字段 | `["<userId>"]` | 负责人字段常要求数组，传单个字符串会报格式错误。 |
| 关联客户/合同/商机 | 对应 numeric `dataId` | 不传记录名称。 |
| 单选 | `items[0].text` | 传选项文本，不传 `items[0].value`。 |
| 多选 | `[items[0].text]` | 不传单个字符串。 |
| 子表单 | `[{ ... }]` | 必须是对象数组，不能仅传 ID 数组。 |

## 4. 人员字段与执行人字段

字段名称包含“人”不代表都传用户 ID。

- `fieldType` 为人员/负责人时，按接口要求传用户 ID 或用户 ID 数组。
- “执行人”等字段可能是选项字段。例如拜访计划的 `array_1` 需传 `["负责人"]`、`["协同人"]` 或 `["自定义"]`，而不是用户 ID。
- 选择“自定义”后，继续检查该选项的 `fieldMap`，填写被启用的人员字段。

## 5. 子表单与上下游 ID

子表单字段必须按对象数组构造：

```json
{
  "array_4": [
    {
      "text_1": 25430570,
      "num_3": 1
    }
  ]
}
```

涉及产品、合同和出库时，需要区分三个 ID：

1. 产品主记录 ID。
2. 产品规格/子产品 ID。
3. 合同关联产品的 `refProductId`。

它们不能互换。创建销售出库单时，先通过 `contract-detail` 查询合同详情，再从关联产品中取得 `refProductId` 和对应产品 ID。出库数量不能超过上游合同关联产品的剩余数量。

## 6. 调试与错误收敛流程

首次调用使用 `--debug`：

```powershell
opencli xbb <command> ... --debug
```

检查输出的 `RequestBody`，重点确认：

- shell 没有破坏 JSON 引号；
- 数字、字符串、数组和对象的类型正确；
- 未提供的字段没有被意外传入；
- `ownerId`、子表单和多选字段仍是数组。

按错误信息增量处理：

| 错误信息 | 处理方法 |
| --- | --- |
| `选项不存在` | 重新查询 `form-get`，改用 `items[].text`。 |
| `字段数据格式错误` | 核对该字段应为单值、数组还是对象数组。 |
| `为必填字段` | 补齐主表或子表单中的对应字段。 |
| `子产品ID校验异常` | 使用产品详情中的子产品 ID，不使用产品主记录 ID。 |
| `产品不存在` | 核对产品 ID、合同产品引用和当前租户。 |
| `执行时间必须大于当前时间` | 使用未来 Unix 秒时间戳。 |
| `数据插入失败` | 对照同类成功详情，逐步补齐必要业务字段，并核对上游关联数据是否仍有效。 |
